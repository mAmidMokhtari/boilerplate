# @repo/ui

Shared, **data-agnostic** UI. Nothing here fetches, imports `@repo/services`,
or knows what a "post" is beyond a type.

## Layout

```
src/
├── components/   shadcn/ui primitives, generated by the CLI. Exported as @repo/ui/<name>
├── blocks/       composed pieces built from primitives.  Exported as @repo/ui/blocks/<name>
├── lib/          utils.ts re-exports `cn` so shadcn's generated imports resolve
└── styles/       globals.css — Tailwind 4 @theme tokens for every app
```

## Adding a shadcn component

```bash
pnpm dlx shadcn@latest add dialog --cwd libs/ui
```

Then, in the generated file, rewrite the CLI's alias imports to relative ones
(`@/lib/utils` → `../lib/utils`, `@/components/x` → `./x`) and replace any
physical Tailwind direction (`ml-2`, `right-0`, `text-left`) with its logical
equivalent (`ms-2`, `end-0`, `text-start`) — lint enforces this and RTL
depends on it. No export map edit is needed: `./*` already resolves
`@repo/ui/<name>` to `src/components/<name>.tsx`.

## Writing a block

- Arrow function typed `React.FC<Props>`, props as a named exported type.
- Every user-visible string arrives via props (a `texts` object with defaults
  when there are several). The library knows no i18n.
- Client interactivity gets `"use client"`; keep it out otherwise so blocks
  stay usable in Server Components.
- Add a `*.stories.tsx` next to it — Storybook runs light/dark and LTR/RTL
  from its toolbar, which is the fastest way to catch a direction bug.

```bash
pnpm storybook          # http://localhost:4400
pnpm nx test ui
```

## Tokens

`src/styles/globals.css` defines the OKLCH palette on `:root` and `.dark`, maps
it into Tailwind via `@theme inline`, and is imported by each app's
`src/styles/globals.css`. Rebrand by editing the token values there — no
component changes needed.
